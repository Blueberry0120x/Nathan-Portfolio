The problem

Keynotes by hand, tables by hand

A keynote is a number on the drawing and a matching row in a table. Simple, until it is a real sheet set. Renumber one callout and every table after it is off; add a note and someone re-types the schedule. On a large civil package that is hours of senior-designer time, and the same QA errors keep coming back.

Before · by hand

Callout by hand, table by hand

Designers place keynote tags one at a time, then build and keep up the keynote table by hand. Every renumber, insertion, or note edit means re-checking the whole schedule. Slow, and easy to get wrong at QA.

After · the engine

One source of truth, two-way sync

A Dynamo engine reads the drawing and writes the table, then reads the table back to the drawing. Renumber once and the tags and schedule stay matched. The designer works on the notes instead of copying them.

How I built it

Five versions, each fixing what the last one showed

Each version fixed a problem the one before it showed me. Those steps are what I would teach at AU.

v2.0
Callout automation. Place and number keynote tags from a controlled list, instead of one at a time.
v3.0
Table generation. Build the keynote table from the tags in the drawing. One direction: drawing → table.
v4.0
Bi-directional sync. Read the table back to the drawing so an edit in either place carries over. This was the hard part, and it is the core of the class.
v5.0
Reusable engine. Rebuilt as a reusable Dynamo tool (DynamicTag / TableNote) so it works beyond one project's standards.

AU Class Proposal
Class title
Keynote Suite: Bi-Directional Keynote & Table Automation in Civil 3D with Dynamo
Session format · track · level
60-minute Instructional Demo  ·  Civil Infrastructure (AEC)  ·  Intermediate
Abstract
Keynotes are one of the last things in Civil 3D sheet production still kept up by hand: a tag on the drawing, a matching row in a table, and a manual re-check every time either one changes. This class walks through the Keynote Suite, a production Dynamo tool that automates keynote callouts and their tables and keeps the two in sync in both directions. Edit a note in the drawing and the schedule updates; change the schedule and the drawing follows. We go through five real versions of the tool, from the first callout automation to a reusable engine, and show the measured 60–80% cut in keynote-and-revision time on live sheet sets. You leave with the design pattern, the problems we hit, and the steps to build the same two-way link into your own standards. You do not need to be a Dynamo expert.
Learning objectives — attendees will be able to
  1. Find where manual keynote and table workflows cost time and cause QA errors in a Civil 3D sheet set.
  2. Explain the bi-directional sync pattern that keeps drawing tags and schedule tables consistent from a single source of truth.
  3. Build the core of a keynote-automation Dynamo graph, including reading from and writing back to the drawing.
  4. Adapt the engine to their own office standards and estimate the time savings on their real projects.
